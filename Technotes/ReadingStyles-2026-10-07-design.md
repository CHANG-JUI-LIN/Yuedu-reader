# 閱讀樣式設計：一鍵套用整套排版

> 日期：2026-10-07
> 狀態：**設計，尚未實作。** §12 第 1、5、6、7 項已於 2026-10-07 定案；第 2、3、4、8 項照建議，實作前可再調。
> 起因：QQ 群反饋「沒有內建主題」「不知道自訂能做到什麼地步」；客戶研究（`.agents/research/2026-10-07-retention-and-pro-conversion.md`）顯示美化是有付費證據的需求，但我們的功能用戶找不到。
> 範圍：可重排文字的閱讀器（`ReaderView`：EPUB、TXT、線上書、青空文庫）。固定頁閱讀器（漫畫、PDF、固定版面 EPUB）不在範圍內。

## 0. 一句話

在幾十個排版參數上面，加一層「閱讀樣式」：用戶在 Aa 面板第一屏看到幾張預覽卡，點一下就換一整套排版（字體、行距、縮排、版心、頁首頁尾…），要細調再進原本的設定。EPUB 多一個開關，決定要照原書排版，還是套用閱讀樣式。

## 1. 已定案（2026-10-07，AskUserQuestion）

| 問題 | 決定 |
|---|---|
| 閱讀樣式和外觀主題的關係 | **樣式是主題裡的一層。** 保留 9/29 定案「閱讀設定全部跟主題切換」：主題照樣帶排版；套用樣式＝把一組排版值寫進目前主題，走既有的單一寫入口。主題包可以指定預設樣式。 |
| 內建主題的來源 | 自己做原生主題，不收錄社群作者的主題包（版權）。 |
| 收費 | 部分免費、其餘 Pro。 |
| EPUB | 加一個開關，決定是否套用原書樣式。 |
| `.qitheme` 相容層的問題 | 這次先不處理。 |
| 排版基準怎麼跟現有設定共存 | **所有排版項目都能「自動」**（§5.3）。 |
| 「套用原書樣式」存在哪 | 全域預設＋每本書例外（§6.2）。 |
| 關掉原書樣式時直排 EPUB 能否轉橫排 | 第一版不行。 |
| 儲存自己的樣式 vs 排版備份 | 共用檔案格式；「排版備份」功能名稱照舊（§8）。 |

**範圍說明：** 本文件處理「閱讀樣式」（排版）。完整的視覺主題包（背景、圖示、卡片、啟動圖）是另一條線，見 §11。

## 2. 名詞與分層

用戶的設想（2026-10-07）把排版分成四層，由下往上疊：

```
排版基準（依內容自動選）   中文小說／英文小說／日文橫排／日文縱排
        ↓
閱讀樣式（用戶選）         標準／經典／寬鬆／緊湊／極簡 …
        ↓
顏色（閱讀背景）           白／紙張／灰／深色／純黑   ← 已存在：ReaderTheme＋自訂背景
        ↓
手動微調                   原本的滑桿與選項           ← 已存在
        ↓
本書覆寫                   只改這本書的幾項           ← 設計中：PerBookReaderSettings
```

- **排版基準**不是「業界標準」，而是我們的基線：第一次打開這類書時最不容易出錯的值。四套分開，因為中、英、日的段落縮排、行高、字體比例、注音、禁則本來就不同。
- **閱讀樣式**是同一個基準上的風格差異，維度只有排版。「文庫本」和「OLED」不是同一層：前者是排版，後者是顏色。
- **顏色**已經有獨立的系統（閱讀背景 `ReaderTheme`、自訂背景、綁定外觀主題），本設計不動它。

## 3. 現況（程式碼事實）

### 3.1 設定存放與寫入

- 排版欄位是 `AppearanceThemeReadingSettings`（`Modules/Core/ReaderCore/Customization/AppearanceThemeReadingSettings.swift`），全部可為空：字體、字級、粗體、文字顏色、行距倍數、字距、段距倍數、四邊邊距、翻頁、捲動、直排、頁首頁尾與間距、章節標題樣式、閱讀背景、段評氣泡、對話氣泡、正則高亮、文字底線。
- **唯一寫入口：** `GlobalSettings.recordReadingSettingEdit`（`Targets/Yuedu/SharedApp/AppearanceThemeReadingApplier.swift:249`）。依「排版生效範圍」（`ReadingSettingsScope.swift`，每項是跟隨主題或跟隨全域）把一次編輯拆成寫進目前主題或全域。
- `Technotes/PerBookReaderSettings-2026-09-15-design.md` §3.1 寫「外觀主題不含排版欄位」——**9/29 之後已不成立**，那份文件實作前要更新。

### 3.2 還沒有設定的排版項目

| 項目 | 現況 |
|---|---|
| 段首縮排 | 沒有設定。TXT 與線上書寫死 `fontSize * 2`（`TXTLazyAttributedStringBuilder.swift`、`NodeAttributedStringBuilder.swift:130`、`OnlineProviderAttributedStringBuilder.swift:609-620`）；EPUB 傳 `firstLineIndent: 0`，只聽原書的 `text-indent`（`EPUBAttributedStringBuilder.swift:500`）。 |
| 文字對齊 | 沒有設定。預設左右對齊；原書寫了 `text-align` 就照原書（`BrowserLayoutPageEngine.swift:883`、`NodeAttributedStringRenderer.swift:1092-1100`）。 |
| 注音（ルビ）大小 | 沒有設定。 |
| 頁碼樣式 | 頁首頁尾已可自訂（`ReaderBarLayout`），但沒有「頁碼樣式」這個獨立概念。 |

閱讀樣式要用到的項目，必須先成為一般設定（可在設定頁調、可存進主題），樣式才有東西可以套。

### 3.3 EPUB 的排版今天由誰決定

EPUB 有兩套引擎：預設的瀏覽器引擎（YueduCoreText 套件 0.7.0，cascade 在套件的 `ComputedStyleTreeBuilder.swift`；App 端設定在 `BrowserLayoutPageEngine.swift:854-897`），以及退回用的舊引擎（`EPUBAttributedStringBuilder` → `HTMLAttributedStringBuilder` → `NodeAttributedStringRenderer`）。兩套各自合併，結果如下：

| 項目 | 用戶設定 | 誰贏 |
|---|---|---|
| 字體 | 有選字體 | **用戶**，含標題；瀏覽器引擎還會跳過載入書內嵌字體（`:898-909`） |
| 字體 | 沒選（「書籍預設字體」） | 原書 |
| 字級 | 用戶字級是根字級 | 原書的相對大小照比例縮放；**原書寫 px/pt 的絕對大小不跟著縮放**（瀏覽器引擎）；舊引擎的 h1 用「標題大小」、h2–h6 用固定倍率 |
| 行距 | 預設值 | **原書**的 `line-height` 有寫就贏（舊引擎只在大於 1.0 時採用） |
| 段距 | — | 瀏覽器引擎：疊加在原書邊距上；舊引擎：原書 `margin-bottom` 有寫就贏 |
| 字距 | 一律套用 | 用戶（兩套引擎都不讀原書 `letter-spacing`） |
| 粗體 | 一律套用 | 用戶 |
| 段首縮排 | 無設定 | 原書 |
| 對齊 | 無設定 | 原書，沒寫則左右對齊 |
| 頁邊距 | 一律套用 | 用戶（原書的區塊邊距在版心內再縮排） |
| 文字顏色 | 主題色為預設 | **原書**的 `color` 有寫就贏，換主題也保留；深色模式下原書的深色 `@media` 贏 |
| 背景 | 主題背景 | 原書 body 的 `background-color` 有寫就贏，除非用戶設了背景圖 |
| 排版方向 | — | 原書（OPF 或 CSS 宣告直排就一律直排；沒有辦法把直排 EPUB 改成橫排） |

**沒有任何「原書樣式」開關。** 相關的只有章節標題的「跟隨閱讀字體」，以及書本自己可宣告的 `zy-fontsize-adjust: fixed`。

### 3.4 TXT、線上書、青空文庫

- **TXT**：用戶設定一律套用，沒有原書樣式可以衝突。縮排寫死兩字。
- **線上書（HTML 章節）**：書源的 CSS 仍可蓋過縮排、對齊、顏色；字體是書源的 `font-family` 優先、用戶字體墊底（和 EPUB 相反）。
- **青空文庫**：匯入時轉成 EPUB，走 EPUB 規則；縮排來自轉出的 XHTML/CSS。直排可由用戶切換（`allowsVerticalWritingMode`）。

### 3.5 已有的語言判斷

`CJKTypographyStyleResolver.style(for:book:conversion:declaredLanguage:)`（`Modules/Core/ReaderCore/CJKTypographyStyleResolver.swift:25-50`）回傳繁、簡、日、韓四種，依序看：內文抽樣（假名 ≥5 → 日文；諺文多於漢字 → 韓文；否則句子投票 75% 決定繁簡）→ 書本宣告的語言 → 介面語言。結果只快取在記憶體。**它不判斷英文／西文書**，選英文基準需要補一個判斷。

### 3.6 Aa 面板

三種閱讀介面（經典、現代、Apple Books）都打開同一個快速面板 `ReaderQuickThemePanelView`，「自定義」再進完整設定 `ReaderSettingsView`（`ReaderView+Toolbars.swift:126, 294, 395`）。預覽卡放在快速面板就能一次覆蓋三種介面。

### 3.7 順帶發現（不在本設計範圍，先記下）

- 舊引擎的註解說 EPUB 標題保留原書字體（`NodeAttributedStringRenderer.swift:39-43, 103-109`），實際上只在沒選字體時成立。
- 瀏覽器引擎完全沒用到章節標題樣式 `chapterTitleStyle`。
- `BookPipelineKind.html.allowsUserSelectedReaderFont` 是 false，但線上書的 `ReadingBook.allowsUserSelectedReaderFont` 回傳 true（`Models.swift:478-482, 505-511`）。

## 4. 資料模型

### 4.1 閱讀樣式＝一組稀疏的排版值

```
ReadingStyle
├─ id、名稱、是否內建、需要 Pro
├─ 基準覆寫：依排版基準分別給值（同一個「經典」在中文和英文書上的數值不同）
│     baseline → AppearanceThemeReadingSettings（只填排版欄位）
└─ 預覽用的範例文字（依基準）
```

- 欄位直接用 `AppearanceThemeReadingSettings` 的排版部分，加上 §3.2 新增的設定。**不另開一套欄位**，樣式能存的就是主題能存的。
- 樣式只管排版欄位：字體、字級、粗體、行距、字距、段距、縮排、對齊、注音大小、邊距、頁首頁尾、章節標題。**不含**顏色、閱讀背景、翻頁、捲動、氣泡、高亮、底線。

### 4.2 套用

1. 依目前這本書算出排版基準（§5）。
2. 取樣式在這個基準的值。
3. 經 `recordReadingSettingEdit` 寫入——照排版生效範圍，跟隨主題的項目寫進目前主題、跟隨全域的寫進全域。**不新增寫入路徑。**
4. 主題（或全域）記下 `readingStyleID`，設定頁才能顯示「目前樣式：經典」。之後用戶手動改任一排版項目，顯示成「經典（已修改）」，並提供「還原為經典」。

### 4.3 主題包指定預設樣式

`AppearanceThemeExtras` 可帶 `readingStyleID`。內建主題包用它來帶出搭配的排版；匯入的 `.qitheme` 沒有這個欄位，照舊直接帶排版值。

## 5. 排版基準

### 5.1 四套

| 基準 | 適用 | 主要差異（數值待 §9 量測） |
|---|---|---|
| 中文 | 繁、簡中文 | 首行縮排兩字、中文行距、頁邊距 |
| 英文 | 西文書 | 襯線字體、英文行高、段落縮排、無中文式段距 |
| 日文橫排 | 日文、橫排 | 日文字體、行距、注音大小 |
| 日文縱排 | 日文、直排（含青空文庫） | 明朝體、縱排行距、注音大小、版心 |

韓文第一版先用中文基準的版面數值，加上韓文字體；量測後再決定是否獨立。

### 5.2 怎麼選

- 由新的 `ReadingBaselineResolver` 決定。CJK 部分直接用 `CJKTypographyStyleResolver` 的結果，再加西文判斷（漢字、假名、諺文都很少時算西文）與排版方向（直排的日文書用日文縱排）。
- 依現有原則：「同一件事只留一條路徑」，語言判斷不另寫一套。

### 5.3 基準怎麼跟現有設定共存（已定案：所有排版項目都能「自動」）

今天的全域設定是**一整套絕對值**（例如字級 18、行距 1.6），沒有「沒設定」的狀態。定案做法：

- 每個排版項目（字體、字級、粗體、行距、字距、段距、段首縮排、對齊、注音大小、四邊邊距）都多一個「自動」狀態，意思是「照這本書的排版基準」。
- 新安裝與從沒動過的項目是「自動」；用戶拖滑桿就變成明確數值；每一列可以「恢復自動」。
- 樣式（§4）裡的每個值也可以是「自動」，例如「寬鬆」只把行距和邊距設成「基準 × 某個倍數」，其餘維持自動。⚠️ 這表示樣式的值要能表達「相對基準」，不只絕對值，資料格式在階段 0 定。

**要處理的三件事：**

1. **三種狀態要分開存。** `AppearanceThemeReadingSettings` 的「沒有值」今天的意思是「主題沒說，用全域」。現在多了「自動」，必須是另一個明確的值，不能共用「沒有值」——和本書覆寫設計裡字體需要三種狀態是同一個問題（`PerBookReaderSettings` §4）。
2. **升級遷移。** 已經裝了 App 的人，現在的每個數值都是他們看慣的樣子。升級後**維持明確數值，不改成自動**，否則所有人的排版會一起變。只有新安裝、以及用戶按「恢復自動」的項目才是自動。
3. **換書時字級跳動。** 都設成自動時，從中文書換到英文書，字級、行距會照基準變。這是刻意的行為，但要讓用戶看得出來：設定頁的值顯示「自動（18 pt）」並註明目前的基準（例如「英文小說」），不要只顯示數字。各基準的字級要在 §9 量測時一起對齊視覺大小，避免換書時字看起來忽大忽小。

字體今天已有類似的狀態：「書籍預設字體」（EPUB）／「系統字體」（其他）。改成依基準選預設字體，就是這個狀態的延伸。

## 6. EPUB「套用原書樣式」開關

### 6.1 語意

| 狀態 | 行為 |
|---|---|
| **開（預設）** | 和今天完全相同（§3.3 的表格）。 |
| **關** | 正文段落改用閱讀樣式的行距、段距、縮排、對齊、字體、文字顏色。 |

- 預設必須是開：App 的原則是照原書畫，而且 EPUB 內容大多是重 CSS 排版。
- 「關」**不是**丟掉整份 CSS。只覆寫一份明確列出的屬性，而且只作用在正文段落；圖片、表格、注音、直排方向、強調（粗、斜、著重號）、註腳、詩歌與引文等有特殊版面的區塊保留原書樣式。哪些算正文段落，由兩套引擎共用的同一條規則判斷（細節在實作設計時定，必須拿 `docs/epub-regression` 的書驗證）。
- 直排 EPUB 關掉開關後仍是直排；能不能強制改成橫排見 §12 待決策 5。

### 6.2 存在哪

- 全域預設值＋每本書覆寫。每本書的值存進 `BookReaderSettingsStore`（已存在，目前只存固定頁設定），**不另開存法**。
- 和本書覆寫設計（PerBookReaderSettings）同一個 resolver 合併。若本書覆寫的閱讀器部分還沒做，這個開關就是它的第一個欄位。

### 6.3 兩套引擎都要改

瀏覽器引擎的 cascade 在 YueduCoreText 套件裡，所以要改套件。依專案的套件流程：App 端依賴新套件 API 的改動放在分支，不進 main；**發佈套件版本前先問作者**。舊引擎在 App 裡，同一條規則要同時實作，並用同一組測試驗證兩邊結果一致。

### 6.4 入口

- 只對 EPUB（非固定版面）顯示。
- 快速面板的樣式卡上方放一列「套用原書樣式」開關；開著的時候樣式卡仍可選，但卡片下方註明「原書已有的行距、縮排、對齊會照原書」。
- 完整設定頁的「排版」區塊也放同一個開關。

## 7. 畫面

### 7.1 快速面板第一屏：樣式卡

- 橫向捲動的預覽卡，每張用**目前這本書的基準**的範例文字畫出來（中文書看到中文、日文縱排書看到縱排）。卡片底下是樣式名稱。
- 預覽用真的排版引擎畫，數值和套用後一致；不能是靜態圖片。
- 目前樣式打勾；手動改過顯示「已修改」。
- 卡片列最後一張是「自訂」，打開完整設定。
- Pro 樣式卡上鎖但可見，點了開付費頁（照 `docs/design.md` §10.2 的「上鎖可見」規則）。

### 7.2 完整設定頁

- 頂端顯示「目前樣式：經典（已修改）」，附「還原為經典」。
- 新增 §3.2 的設定列：段首縮排、對齊、注音大小（只對有注音的書顯示）。
- 「儲存為新樣式」（Pro）。

### 7.3 無障礙

- 每張卡是一個按鈕，標籤是樣式名稱，值是「已選取」或「需要 Pro」；預覽文字設 `accessibilityHidden(true)`，不唸範例內容。
- 「已修改」用文字表達，不只靠圖示。
- 開關照原生 `Toggle` 標籤，不自己拼。

### 7.4 新增本地化字串（候選，五個 lproj 都要加）

閱讀樣式、目前樣式、已修改、還原為%@、儲存為新樣式、套用原書樣式、原書已有的行距、縮排、對齊會照原書、段首縮排、對齊、注音大小、自動，以及每個內建樣式名稱。

## 8. 收費

依研究結論：**原本免費的不收費**（每個競品的一星高峰都來自「原本免費、後來收費」）。

| 免費 | Pro |
|---|---|
| 依內容自動選的排版基準 | 其他內建樣式（經典、寬鬆、緊湊、極簡…） |
| 「標準」樣式 | 儲存自己的樣式 |
| 所有手動設定（滑桿、選項），含新增的縮排、對齊、注音大小 | 每本書套不同樣式（接本書覆寫） |
| EPUB「套用原書樣式」開關 | |

- `PremiumFeature` 新增一個 case，放進「讀得更舒服」那一類，並給專屬的付費頁標題（`PremiumFeatureTests` 會檢查）。
- 現有的 Pro 功能「排版備份」（整套排版匯出匯入）和「儲存自己的樣式」共用檔案格式（已定案）：匯入的排版備份變成一個自訂樣式。**「排版備份」的功能名稱、入口、按鈕行為照舊**，只換底層格式；舊格式的備份檔要能繼續匯入。

## 9. 數值怎麼定：量測，不憑感覺

### 9.1 三個來源

1. **成熟閱讀器的預設值**：Apple Books、Kindle、Kobo 在同一台裝置上，第一次開書時的字級、行寬（每行字數）、行距、邊距。在實機上量、截圖存檔，不引用網路上的二手數字。
2. **實體出版物**：日文縱排參考文庫本（角川、新潮、岩波等）的每行字數、每頁行數、天地與內外邊距、字體感；中文參考繁、簡出版社的小說；英文參考平裝小說。記錄來源書名與量法。
3. **我們自己的可讀性測試**：固定範例 × 機型（§9.2），看每行字數、每頁密度、換行與標點品質。

### 9.2 固定範例與機型

| 範例 | 用途 |
|---|---|
| 中文長篇（繁、簡各一） | 中文基準 |
| 英文小說 | 英文基準 |
| 日文橫排 | 日文橫排基準 |
| 日文縱排＋注音（青空文庫） | 日文縱排基準、注音 |
| 大量對話 | 段距、縮排 |
| 大量標點 | 標點擠壓、行尾禁則 |

機型：iPhone SE（最小）、一般 Pro、Pro Max、iPad。範例放 `docs/` 下固定的位置，量測結果和截圖一起存檔。

### 9.3 驗收

每個基準和樣式要寫下：目標每行字數範圍、每頁行數範圍，在四種機型上都落在範圍內。這是數值的依據，不是事後美化。

## 10. 分階段

| 階段 | 內容 | 驗證 |
|---|---|---|
| 0 | 把 §3.2 的項目做成一般設定（段首縮排、對齊、注音大小）；所有排版項目加上「自動」狀態與基準解析（§5）；升級遷移維持明確數值。**不加樣式**。 | 升級用戶的輸出和今天完全相同（快照測試）；新安裝走自動；新設定在 TXT、線上書、EPUB 兩套引擎都生效 |
| 1 | §9 量測，定出四套基準和第一批樣式的數值。 | 量測紀錄＋截圖；每行字數、每頁行數落在範圍內 |
| 2 | 樣式模型與套用（§4）、快速面板樣式卡（§7.1）、完整設定頁（§7.2）、Pro 上鎖。 | 套用後寫進正確的主題／全域；換主題時樣式跟著主題；手動修改顯示「已修改」；VoiceOver |
| 3 | EPUB「套用原書樣式」開關（§6），含套件改動。 | `docs/epub-regression` 的書在開、關兩種狀態截圖比對；開＝今天的輸出 |
| 4 | 儲存自己的樣式、每本書套樣式（接本書覆寫）。 | |

每個階段先寫會失敗的測試再改程式；動到直排時加跑 `CoreTextWritingModeTests`。

## 11. 另一條線：內建視覺主題包（記下，不在本文件）

QQ 群說的「沒有內建主題」，有一部分指的是完整的視覺主題包（背景、圖示、卡片、啟動圖、字體），像社群作者用 `.qitheme` 做的那種。現況：內建只有「默認」加 6 個純色（`AppearanceThemePreset.freeSolidPresets`），`bundledThemePacks` 是空的。已定案自己做、部分免費。它可以用 §4.3 帶出搭配的閱讀樣式。需要另寫設計：素材來源與授權（含可商用字體）、免費與 Pro 各幾套、包大小。

## 12. 決策紀錄

| # | 問題 | 結果 | 備註 |
|---|---|---|---|
| 1 | 基準怎麼跟絕對值的設定共存（§5.3） | **定案：所有排版項目都能「自動」** | 原建議只給四項加自動；作者選全部。升級用戶維持明確數值 |
| 2 | 第一版內建幾個樣式、叫什麼 | 照建議：「標準」加三到四個，量測後再定名稱和數量 | 不先承諾「五套」 |
| 3 | 樣式卡放哪 | 照建議：快速面板第一屏 | 三種介面共用同一個面板 |
| 4 | 「套用原書樣式」的預設值 | 照建議：開（等於今天） | 升級後沒人被改掉排版 |
| 5 | 關掉原書樣式時，直排 EPUB 能不能改成橫排 | **定案：第一版不行** | 縱中橫、圖片位置照直排設計，之後再評估 |
| 6 | 原書樣式開關是全域、每本書，還是兩者 | **定案：全域預設＋每本書例外**，存進 `BookReaderSettingsStore` | 存法只有一套 |
| 7 | 「儲存自己的樣式」和既有的「排版備份」 | **定案：共用檔案格式**，「排版備份」名稱與入口照舊 | 舊格式備份檔要能繼續匯入 |
| 8 | 英文基準的判斷 | 照建議：在 `CJKTypographyStyleResolver` 旁補西文判斷，共用同一份抽樣 | 不另寫語言判斷 |
