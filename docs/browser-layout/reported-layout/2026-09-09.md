正常 EPUB 入口仍固定使用 `CoreTextPageEngine`（Legacy）。`BrowserLayoutFeature.mode = .legacy`、`browserEnabled = false`，`EPUBPageRenderer.load` 直接指定舊引擎。只有 DEBUG 模擬器以 `-reader-interaction-browser-auto` 啟動時，才注入 BrowserLayoutPageEngine 的 Auto 模式。`43481b6c` 明確恢復 Legacy 路由；後續 `8b886d62` 保留模擬器驗收入口。

## 根因範圍

### 畫冊：scanner 放行，但行內裝飾沒有送到繪製

書中 `.bti` 指定白字，`.bti b` 指定 `background-color:#5f52a0` 與 padding。BoxTreeBuilder 將 `<b>` 收成 inline runs；PageWalker 的一般文字路徑只把文字顏色、字型、範圍與 CTLine 送入 StepText，沒有送出該 inline 背景的 fill。現有背景 decoration 路徑處理 block box，不能據此認定 inline decoration 已支援。

實際 PNG 中紫色底線、圖片與副標均存在，但白字標題所在區域沒有紫底。這是「scanner supported」不等於「完整呈現」的具體案例。後續須補行內裝飾的 layout／fragment／paint 契約與像素驗收，不能僅檢查 source text 存在。

### 技能面板：真正缺少定位與 Flex 能力

`.skill-name`／`.skill-score` 使用 `position:absolute`、left/right/top 與固定寬度；同時使用 `display:flex`、align-items、justify-content。Auto 目前按章檢查能力，遇到拒絕理由就整章回到 Legacy。它沒有渲染兩套結果再比較畫面品質，也沒有保證 Legacy 會保留更多作者樣式。

Flex／定位屬 layout 能力，Lexbor 長屬性 mapping 完成本身不會補出這些排版算法。後續須完成相關 formatting context、文字與裝飾幾何及跨頁驗收，再調整 admission；不能用放寬 scanner 取代實作。

同一本書共有 7 章包含同類面板 class：第 2、13、48、100、169、414、447 章。這是原 EPUB markup 普查，並非宣稱 7 章都已逐張重現；[對應章節與 class](2026-09-09-related-panels.json)。
