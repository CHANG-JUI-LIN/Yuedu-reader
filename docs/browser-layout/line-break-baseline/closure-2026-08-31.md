## CoreText advance determinism follow-up

The 7,350-chapter same-process closure replay subsequently exposed two plain
prose chapters whose page count, page/source ranges, logical line count,
fragment count, and vertical geometry were identical, but whose raw horizontal
advance differed by `6.984919309616e-10pt` between equivalent `CTLine`
instances. The first differing doubles were 49,152 ULP apart.

The production boundary now canonicalizes only `CTLine` horizontal advance by
clearing its lowest 16 mantissa bits. Ascent and descent remain untouched. This
retains roughly 36 bits of relative precision and changes an approximately
100pt advance by less than `1e-9pt`; it is not a visual offset or a geometry
exception.

That generic rule changed the stored digest for exactly 18 already-updated
rows. The separately gated
`coretext-advance-normalization-attribution-2026-09-02.tsv` updater required
the changed-spine set to equal those 18 rows exactly and verified aggregate
pages `295 → 295` and text fragments `12,958 → 12,958` before writing. No row
outside that attribution was changed. The control sentinel was then removed.
