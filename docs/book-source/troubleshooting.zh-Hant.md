# 常見症狀對照表

> 其他章節：[快速開始](quickstart.zh-Hant.md) · [規則語法速查](rule-syntax.zh-Hant.md) · [與 Legado 的差異](legado-differences.zh-Hant.md)
> 简体中文：[常见症状对照表](troubleshooting.zh-Hans.md)

書源壞掉時，先跑「測試書源」（五階段驗證）確定是哪一階段，再開「調試規則」看逐步日誌，最後回到本頁對照症狀。

調試流程複習：書源列表長按書源 →「測試書源」；書源編輯器 →「⋯」→「調試規則」→ 跑對應分頁。日誌從上到下：**原始數據 → 規則解析 → 提取 → 正則替換 → JS → 最終值**，從「最終值」往回找第一個「（空）」或 `ERROR` 的步驟。

## A. 五階段驗證失敗分類

「測試書源」的結果分三類，先認清問題歸誰：

| 分類 | 意義 | 怎麼辦 |
| --- | --- | --- |
| 規則缺失 | 書源沒填該階段規則欄位 | 補上對應欄位；或這本書源根本不支援該階段（正常） |
| 解析失效 | 有規則但結果空／錯 | 本頁 B~F 的症狀，多數自己能修 |
| 環境問題 | 網路／防護／登入因素 | 檢查網路；換網域測試；有 Cloudflare 時手動過驗證；需要登入的見 F |

書源列表徽章：**驗證通過**（綠）＝五階段全過；**抓取異常**＝搜索/詳情/目錄失敗；**正文異常**＝只有正文失敗。響應毫秒數是最近一次驗證耗時。

## B. 搜索階段

| 症狀 | 常見原因 | 修正 |
| --- | --- | --- |
| 搜索完全無結果，原始數據正常 | `bookList` 選擇器選錯或範圍太小 | 用瀏覽器開發者工具看搜索結果 HTML；調試日誌「原始數據」直接貼出前 200 字元比對 |
| 搜索無結果，URL 看起來怪 | 關鍵字編碼：GBK 站點沒設 charset | 搜索 URL 加 `,{"charset":"gbk"}`（或 `"gb2312"`） |
| 搜索無結果，但同一個源在 Legado 正常 | URL 模板用了規則字串語法 | 檢查 `{{key}}` 是否被寫在規則欄位而不是 URL 欄位；`{{js:…}}` 前綴移除 |
| 有結果但書名/作者/封面為空 | 欄位規則相對於 `bookList` 的範圍錯誤 | 欄位規則預設以每本書條目為根，檢查是否漏了相對選擇（如直接 `@text` 而不是 `.title@text`）；`coverUrl` 抓不到時改 `img@src` |
| 結果只有一部分書 | `bookList` 只匹配到部分節點 | 改用更廣的選擇器 + `||` 併第二條規則；或 `@css:A@@B` 鏈式 |
| 搜索結果點不進去 | `bookUrl` 沒填或相對 URL 沒解析 | 補 `bookUrl` 規則（`@href` 會自動解析成絕對 URL） |
| 搜索正常但「測試書源」標記搜索失效 | 驗證關鍵字太冷門 | 書源編輯器「校驗關鍵字」填該站常見搜索詞；或用書架已有該源書名 |

## C. 詳情階段

| 症狀 | 常見原因 | 修正 |
| --- | --- | --- |
| 詳情頁所有欄位空白 | 詳情規則全空（只有搜索規則的書源） | 若 `tocUrl` 能拿到就不用補欄位；點進去讀不了再補 |
| 書名/作者對，簡介、封面空 | meta 標籤（og: 系列）規則過時 | 詳情頁常見寫法：`@css:[property=og:title]@content`、`@css:[property=og:image]@content`；網站改版就更新 |
| 詳情 URL 本身打不開 | 詳情走的是 `ruleSearch.bookUrl` 抓的網址 | 檢查 bookUrl 規則；網站對 Referer 敏感就加請求頭 |
| 詳情需要先跑 JS 初始化 | 缺「預處理規則」 | 詳情分頁的「預處理規則」填入（結果是 JSON 物件時，其鍵就是後續規則名） |
| 更新時間/字數為空 | 網站沒這欄位 | 留空即可，不影響閱讀 |

## D. 目錄階段

| 症狀 | 常見原因 | 修正 |
| --- | --- | --- |
| 目錄完全空白 | `chapterList` 選擇器過時（網站改版最常見） | 用調試器「目錄」分頁看「原始數據」，比對選擇器 |
| 目錄只有一項或幾項 | 選擇器只命中容器而非列表項 | 改選列表項本身（如 `#list a` 而非 `#list`） |
| 章節順序顛倒 | 網站目錄是倒序 | `chapterList` 前面加 `-`（如 `-tag.li`） |
| 章節標題是 HTML 夾帶廣告 | `chapterName` 取太多 | `@text` 改 `@textNodes`；或加 `##廣告字樣##` 淨化 |
| 章節 URL 打不開正文 | 相對 URL 沒解析、或漏了選項 | `@href` 自動絕對化；需要 WebView 的網站：`tag.a@href##$##,{"webView":true}` |
| 目錄只有第一頁 | 缺「目錄下一頁規則」 | 補 `nextTocUrl`（支援單 URL 或規則）；JS 回 `[]`/`null`/空字串＝停止 |
| 捲/卷標記亂掉 | `isVolume` 判斷規則錯誤 | 卷標題行通常標記 `isVolume` 為真；不確定就留空（App 會自動判斷「卷分隔標題」） |
| 章節帶 VIP/付費無法讀 | 免費站可忽略 | 檢查 `isVip`/`isPay`；此類書源在 App 的行為與 Legado 相同（仍會嘗試抓取） |

## E. 正文階段

| 症狀 | 常見原因 | 修正 |
| --- | --- | --- |
| 正文空白，日誌顯示 HTML 正常 | `content` 規則選錯節點 | 看「原始數據」找正文容器 id/class；常見：`#content@html`、`#chaptercontent@text` |
| 正文是整頁 HTML 垃圾 | content 用了 `@all`/`@html` 取到整個頁面 | 改取正文容器；加淨化正則 |
| 正文含廣告/網址水印 | 缺淨化規則 | `##<div class="ad">[\s\S]*?</div>|本站網址.*##`（`[\s\S]*?` 非貪婪，注意結尾 `##` 別省） |
| 正文只有一半，卡在「下一頁」 | 網站正文分頁 | 補「正文下一頁 URL 規則」`nextContentUrl`；支援規則或 URL 陣列 |
| 正文亂碼 | 站點非 UTF-8 | 章節 URL 選項加 `"charset":"gbk"`（或請求頭指定） |
| 正文靠 JS 解密（webJs） | 缺「WebView JS」 | 填入解密 JS；注意：**webJs 必須回傳非空值**才算成功，否則無限重試；回傳值會被當成正文或資源來源 |
| 章節名稱（正文標題）錯 | `title` 規則問題 | 正文分頁「章節名稱規則」；空則用目錄標題 |
| 換源後章節對不齊 | — | 屬預期行為：不同源章節數不同，App 會依章節名對齊（換源搜索時勾「順便抓取目錄」可加速對齊） |
| 正文圖片是亂碼（base64 圖） | 缺圖片解密 | 「圖片解密」填 base64 解密規則；漫畫源 `content` 回圖片陣列時，欄位請保持規則而非 URL |
| 聽書源沒有音頻 | `sourceRegex` 沒填對 | 資源正則填媒體 URL 樣式（`.*\.(mp3|m4a).*` 等）；配合 `webJs` 嗅探流程 |

## F. JS 與登入

| 症狀 | 常見原因 | 修正 |
| --- | --- | --- |
| 日誌出現 `ERROR:` | JS 執行失敗 | 展開該條看錯誤訊息；對照[差異表](legado-differences.zh-Hant.md)檢查 API |
| `ERROR: UnsupportedLegadoAPIError` | 用了白名單外的 Java 類別 | 改寫成已支援 API；RSA 類無解 |
| JS 回空字串但 Legado 正常 | 用了 `{{key}}`/`{{js:}}` 等差異語法 | 見[差異表第 3 節](legado-differences.zh-Hant.md) |
| 一直轉圈/等待 | 網站慢 | 檢查 `respondTime`（超時毫秒，預設 180000）；請求本身 30 秒 JS 超時 |
| 需要登入的站 | 沒走登入流程 | 「基本」分頁填「登入頁 URL」→ 書源列表長按 →「Cookie 驗證登入」；登入後 cookie 自動帶上 |
| 登入後仍被導回登入頁 | `loginCheckJs` 誤判 | 檢查「登入檢查 JS」是否太嚴格（它回傳 true＝判定要登入） |
| Cloudflare 人機驗證卡住 | 站點防護 | 依提示手動通過後會自動重試；仍失敗通常是站點對 iOS 網路環境封鎖 |

## G. 其他

| 症狀 | 常見原因 | 修正 |
| --- | --- | --- |
| 搜索時被暫時跳過（「暫跳 n」） | 連續失敗 3 次進入冷卻 | 等冷卻（最長 1 小時）；修好規則後自然恢復 |
| 書源突然全失效 | 站點改版 | 「書源驗證」重新全量檢查，看哪些分類變化 |
| 某些書源怎麼都抓不到 | 站點反爬 | 檢查「請求頭」是否帶完整 UA；`concurrentRate` 設低防封（如 `0.5`） |
| 匯入書源失敗/無回應 | JSON 格式或編碼問題 | 只匯入單源測試；確認是 Legado 3.0 格式（`bookSourceUrl` 頂層鍵） |
| 結果在 Legado 正常但這裡不同 | 引擎差異 | 逐段比對調試日誌與 Legado 的 `BookSourceDebugActivity`（兩邊標記格式相同）；用[差異表](legado-differences.zh-Hant.md)定位 |

## 回報問題模板

自己修不好、需要回報時，附上：

1. 書源 JSON（書源列表 →「⋯」→「複製源」）
2. 「調試規則」失敗分頁的日誌截圖（**展開失敗那幾條**）
3. 一句話：哪一階段失敗、在 Legado 上是否正常

回報管道見專案 GitHub（Issues）或 README 中的社群連結。
