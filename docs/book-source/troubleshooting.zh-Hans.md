# 常见症状对照表

> 其他章节：[快速开始](quickstart.zh-Hans.md) · [规则语法速查](rule-syntax.zh-Hans.md) · [与 Legado 的差异](legado-differences.zh-Hans.md)
> 繁體中文：[常見症狀對照表](troubleshooting.zh-Hant.md)

书源坏掉时，先跑「测试书源」（五阶段验证）确定是哪一阶段，再开「调试规则」看逐步日志，最后回到本页对照症状。

调试流程复习：书源列表长按书源 →「测试书源」；书源编辑器 →「⋯」→「调试规则」→ 跑对应分页。日志从上到下：**原始数据 → 规则解析 → 提取 → 正则替换 → JS → 最终值**，从「最终值」往回找第一个「（空）」或 `ERROR` 的步骤。

> 说明：书源编辑器与调试器内的字段标签在 App 内固定显示繁体中文（不随系统语言变化），下列标签照 App 实际显示。

## A. 五阶段验证失败分类

「测试书源」的结果分三类，先认清问题归谁：

| 分类 | 意义 | 怎么办 |
| --- | --- | --- |
| 规则缺失 | 书源没填该阶段规则字段 | 补上对应字段；或这书源根本不支持该阶段（正常） |
| 解析失效 | 有规则但结果空／错 | 本页 B~F 的症状，多数自己能修 |
| 环境问题 | 网络／防护／登录因素 | 检查网络；换网域测试；有 Cloudflare 时手动过验证；需要登录的见 F |

书源列表徽章：**验证通过**（绿）＝五阶段全过；**抓取异常**＝搜索/详情/目录失败；**正文异常**＝只有正文失败。响应毫秒数是最近一次验证耗时。

## B. 搜索阶段

| 症状 | 常见原因 | 修正 |
| --- | --- | --- |
| 搜索完全无结果，原始数据正常 | `bookList` 选择器选错或范围太小 | 用浏览器开发者工具看搜索结果 HTML；调试日志「原始数据」直接贴出前 200 字元比对 |
| 搜索无结果，URL 看起来怪 | 关键字编码：GBK 站点没设 charset | 搜索 URL 加 `,{"charset":"gbk"}`（或 `"gb2312"`） |
| 搜索无结果，但同一个源在 Legado 正常 | URL 模板用了规则字符串语法 | 检查 `{{key}}` 是否写在规则字段而不是 URL 字段；`{{js:…}}` 前缀移除 |
| 有结果但书名/作者/封面为空 | 字段规则相对于 `bookList` 的层级错误 | 字段规则预设以每本书条目为根，检查是否漏了相对选择（如直接 `@text` 而不是 `.title@text`）；`coverUrl` 抓不到时改 `img@src` |
| 结果只有一部分书 | `bookList` 只匹配到部分节点 | 改用更广的选择器 + `||` 并第二条规则；或 `@css:A@@B` 链式 |
| 搜索结果点不进去 | `bookUrl` 没填或相对 URL 没解析 | 补 `bookUrl` 规则（`@href` 会自动解析成绝对 URL） |
| 搜索正常但「测试书源」标记搜索失败 | 验证关键字太冷门 | 书源编辑器「校驗關鍵字」填该站常见搜索词；或用书架上已有该源书名 |

## C. 详情阶段

| 症状 | 常见原因 | 修正 |
| --- | --- | --- |
| 详情页所有字段空白 | 详情规则全空（只有搜索规则的书源） | 若 `tocUrl` 能拿到就不用补字段；点进去读不了再补 |
| 书名/作者对，简介、封面空 | meta 标签（og: 系列）规则过时 | 详情页常见写法：`@css:[property=og:title]@content`、`@css:[property=og:image]@content`；网站改版就更新 |
| 详情 URL 本身打不开 | 详情走的是 `ruleSearch.bookUrl` 抓的网址 | 检查 bookUrl 规则；网站对 Referer 敏感就加请求头 |
| 详情需要先跑 JS 初始化 | 缺「預處理規則」 | 详情分页的「預處理規則」填入（结果是 JSON 对象时，其键就是后续规则名） |
| 更新時間/字數为空 | 网站没这字段 | 留空即可，不影响阅读 |

## D. 目录阶段

| 症状 | 常见原因 | 修正 |
| --- | --- | --- |
| 目录完全空白 | `chapterList` 选择器过时（网站改版最常见） | 用调试器「目录」分页看「原始数据」，比对选择器 |
| 目录只有一项或几项 | 选择器只命中容器而非列表项 | 改选列表项本身（如 `#list a` 而非 `#list`） |
| 章节顺序颠倒 | 网站目录是倒序 | `chapterList` 前面加 `-`（如 `-tag.li`） |
| 章节标题是 HTML 夹带广告 | `chapterName` 取太多 | `@text` 改 `@textNodes`；或加 `##廣告字樣##` 净化 |
| 章节 URL 打不开正文 | 相对 URL 没解析、或漏了选项 | `@href` 自动绝对化；需要 WebView 的网站：`tag.a@href##$##,{"webView":true}` |
| 目录只有第一页 | 缺「目錄下一頁規則」 | 补 `nextTocUrl`（支持单 URL 或规则）；JS 回 `[]`/`null`/空字符串＝停止 |
| 卷/卷标记乱掉 | `isVolume` 判断规则错误 | 卷标题行通常标记 `isVolume` 为真；不确定就留空（App 会自动判断「卷分隔标题」） |
| 章节带 VIP/付费无法读 | 免费站可忽略 | 检查 `isVip`/`isPay`；此类书源在 App 的行为与 Legado 相同（仍会尝试抓取） |

## E. 正文阶段

| 症状 | 常见原因 | 修正 |
| --- | --- | --- |
| 正文空白，日志显示 HTML 正常 | `content` 规则选错节点 | 看「原始数据」找正文容器 id/class；常见：`#content@html`、`#chaptercontent@text` |
| 正文是整页 HTML 垃圾 | content 用了 `@all`/`@html` 取到整个页面 | 改取正文容器；加净化正则 |
| 正文含广告/网址水印 | 缺净化规则 | `##<div class="ad">[\s\S]*?</div>|本站網址.*##`（`[\s\S]*?` 非贪婪，注意结尾 `##` 别省） |
| 正文只有一半，卡在「下一頁」 | 网站正文分页 | 补「正文下一頁 URL 規則」`nextContentUrl`；支持规则或 URL 数组 |
| 正文乱码 | 站点非 UTF-8 | 章节 URL 选项加 `"charset":"gbk"`（或请求头指定） |
| 正文靠 JS 解密（webJs） | 缺「WebView JS」 | 填入解密 JS；注意：**webJs 必须回传非空值**才算成功，否则无限重试；回传值会被当成正文或资源来源 |
| 章节标题（正文标题）错 | `title` 规则问题 | 正文分页「章節名稱規則」；空则用目录标题 |
| 换源后章节对不齐 | — | 属预期行为：不同源章节数不同，App 会依章节名对齐（换源搜索时勾「顺带抓取目录」可加速对齐） |
| 正文图片是乱码（base64 图） | 缺图片解密 | 「圖片解密」填 base64 解密规则；漫画源 `content` 回图片数组时，字段请保持规则而非 URL |
| 听书源没有音频 | `sourceRegex` 没填对 | 资源正则填媒体 URL 样式（`.*\.(mp3|m4a).*` 等）；配合 `webJs` 嗅探流程 |

## F. JS 与登录

| 症状 | 常见原因 | 修正 |
| --- | --- | --- |
| 日志出现 `ERROR:` | JS 执行失败 | 展开该条看错误信息；对照[差异表](legado-differences.zh-Hans.md)检查 API |
| `ERROR: UnsupportedLegadoAPIError` | 用了白名单外的 Java 类 | 改写成已支持 API；RSA 类无解 |
| JS 回空字符串但 Legado 正常 | 用了 `{{key}}`/`{{js:}}` 等差异语法 | 见[差异表第 3 节](legado-differences.zh-Hans.md) |
| 一直转圈/等待 | 网站慢 | 检查 `respondTime`（超时毫秒，预设 180000）；请求本身 30 秒 JS 超时 |
| 需要登录的站 | 没走登录流程 | 「基本」分页填「登入頁 URL」→ 书源列表长按 →「Cookie 驗證登入」；登录后 cookie 自动带上 |
| 登录后仍被导回登录页 | `loginCheckJs` 误判 | 检查「登入檢查 JS」是否太严格（它回传 true＝判定要登录） |
| Cloudflare 人机验证卡住 | 站点防护 | 依提示手动通过后会自动重试；仍失败通常是站点对 iOS 网络环境封锁 |

## G. 其他

| 症状 | 常见原因 | 修正 |
| --- | --- | --- |
| 搜索时被暂时跳过（「暂跳 n」） | 连续失败 3 次进入冷却 | 等冷却（最长 1 小时）；修好规则后自然恢复 |
| 书源突然全失效 | 站点改版 | 「书源验证」重新全量检查，看哪些分类变化 |
| 某些书源怎么都抓不到 | 站点反爬 | 检查「請求頭」是否带完整 UA；`concurrentRate` 设低防封（如 `0.5`） |
| 导入书源失败/无回应 | JSON 格式或编码问题 | 只导入单源测试；确认是 Legado 3.0 格式（`bookSourceUrl` 顶层键） |
| 结果在 Legado 正常但这里不同 | 引擎差异 | 逐段比对调试日志与 Legado 的 `BookSourceDebugActivity`（两边标记格式相同）；用[差异表](legado-differences.zh-Hans.md)定位 |

## 回报问题模板

自己修不好、需要回报时，附上：

1. 书源 JSON（书源列表 →「⋯」→「复制源」）
2. 「调试规则」失败分页的日志截图（**展开失败那几条**）
3. 一句话：哪一阶段失败、在 Legado 上是否正常

回报渠道见项目 GitHub（Issues）或 README 中的社群链接。
