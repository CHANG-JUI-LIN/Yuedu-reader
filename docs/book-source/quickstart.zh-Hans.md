# 快速开始：导入、验证与调试书源

> 其他章节：[规则语法速查](rule-syntax.zh-Hans.md) · [与 Legado 的差异](legado-differences.zh-Hans.md) · [常见症状对照表](troubleshooting.zh-Hans.md)
> 繁體中文：[快速開始](quickstart.zh-Hant.md)

Yuedu 直接读取 **Legado 格式的书源 JSON**（`ruleBookSource` 结构），不需要转换。多数在 Legado 上运行正常的书源可以直接导入，少数会因为规则引擎的差异而失效——本指南教你在 App 内完成「导入 → 验证 → 调试 → 修正」的完整流程。

## 适用范围

本指南涵盖的项目：

- **书源**（文字小说／听书／漫画类型的 `bookSourceType` 0/1/2）
- 书源的 **搜索、发现（探索）、详情、目录、正文** 五个阶段

不涵盖的独立系统（各有自己的设置界面与格式）：TTS 语音源、RSS 订阅源、OPDS 目录、WebDAV、替换规则。

## 1. 导入书源

书源列表（App「书库」→「书源」分页）右上角点「**+**」，或按空状态提示，即可打开导入：

- **粘贴 JSON**：直接粘贴 Legado 导出的书源 JSON（单个 `{}` 或数组 `[]` 皆可）
- **从文件选取**：支持 `.json`、`.yds`、`.xbs`、`.mrs` 文件
- 导入后可在书源列表用「更多 → 复制源／粘贴源」搬移书源 JSON

## 2. 测试书源：五阶段验证

导入后第一件事：在书源列表**长按（或左滑）书源 →「测试书源」**，对单一书源跑五阶段验证：

| 阶段 | 检查内容 |
| --- | --- |
| 检查搜索 | 用测试关键字搜索，解析 `ruleSearch.bookList` |
| 检查发现 | 解析 `exploreUrl` 与 `ruleExplore.bookList` |
| 检查详情 | 实际抓取第一本书的详情页并解析 `ruleBookInfo`；搜索结果即使已有目录 URL 也不会跳过 |
| 检查目录 | 使用详情阶段产生的 URL 与运行变量抓取目录，验证至少有可加载章节并检查常见 API 错误包装 |
| 检查正文 | 抓取并解析第一个可加载章节，验证实际正文不为空 |

验证结果页会显示五个阶段各自的通过／失败状态（⚪ 绿＝通过，红＝失败）、每阶段耗时（毫秒），失败的阶段再按 `FailureCategory` 分类：

| 分类 | 含义 | 通常是谁的问题 |
| --- | --- | --- |
| 规则缺失 | 书源根本没填该阶段的规则字段，或规则为空 | 书源作者 |
| 解析失效 | 有规则但解析后结果为空／错误 | 规则与网站现状不符，或用到本 App 不支持的语法 |
| 环境问题 | 网络、防护（Cloudflare）、登录等外部因素 | 网站／使用者环境 |

书源列表每一行会显示徽章：**验证通过**、**抓取异常**、**正文异常**，以及最近一次响应毫秒数；列表顶部可筛选「全部／抓取异常／正文异常」。

> 一次验证所有书源：书源列表右上角「书源验证」→「开始验证」（可勾选要检查的阶段，测试关键字预设为书架上该来源的书名）。

## 3. 调试规则：逐步日志

验证只能告诉你「哪个阶段失败」；要知道「**哪一条规则、哪一步**失败」，用规则调试器：

「书源」分页点开书源 → **编辑书源** → 右上角「⋯（更多）」→「**调试规则**」。

调试器有五个分页：**搜索／详情／目录／正文／全流程**。输入关键字（搜索、全流程）或 URL（详情、目录、正文）后按「执行」，日志会逐步印出：

1. **原始数据**：收到的 HTML／JSON 类型与长度（前 200 字元预览）
2. **规则解析**：规则被拆成哪些段落、各段模式（CSS／XPath／JSON／JS／Regex）
3. **提取 #n**：每一段规则的输入与提取结果
4. **正则替换 #n**：`##pattern##replacement##` 替换前后对照
5. **JS 执行 #n**：执行的 JS 与回传值（出错时会看到 `ERROR:`）
6. **最终值／最终列表**：整条规则链的最终输出与耗时

对照 Legado 的经验：日志格式刻意采用与 Legado `BookSourceDebugActivity` 相同的标记（`[Rule Parsed]`、`[String Extracted #n]`、`[Final Result]`…），熟悉 Legado 调试的用户可以无缝对照。

**判读原则**：从「最终值」往回找第一个显示「（空）」或 `ERROR` 的步骤——空结果的那一段就是断点。

## 4. 需要登录的书源

书源编辑器「基本」分页有**登录页 URL**、**登录 UI**、**登录检查 JS** 三个字段：

- 填了登录页 URL 的书源，可在书源列表长按 →「**Cookie 验证登录**」用内置浏览器登录
- **登录检查 JS**：登录后在搜索响应上执行，判定是否仍被导向登录页；非空时搜索前会先检查登录状态
- 登录取得的 cookie 会自动保存并在后续请求带上（详见[与 Legado 的差异](legado-differences.zh-Hans.md)）

## 5. 回报问题前，先准备这些

向书源作者或本项目回报书源问题时，请附上：

1. **书源 JSON**（书源列表 → 更多 →「复制源」）
2. **失败阶段的调试日志**：编辑书源 → 更多 →「调试规则」跑对应分页，把结果截图（若只截图，请展开可疑的那几条日志看完整内容）
3. **一句话描述**：哪个阶段失败（搜索无结果／目录空白／正文空白…）、在 Legado 上是否正常

先对照[常见症状对照表](troubleshooting.zh-Hans.md)，多数问题在 App 内就能自己修好。
