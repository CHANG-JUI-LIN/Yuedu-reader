# 快速開始：匯入、驗證與調試書源

> 其他章節：[規則語法速查](rule-syntax.zh-Hant.md) · [與 Legado 的差異](legado-differences.zh-Hant.md) · [常見症狀對照表](troubleshooting.zh-Hant.md)
> 简体中文：[快速开始](quickstart.zh-Hans.md)

Yuedu 直接讀取 **Legado 格式的書源 JSON**（`ruleBookSource` 結構），不需要轉換。多數在 Legado 上運作正常的書源可以直接匯入，少數會因為規則引擎的差異而失效——這份指南教你在 App 內完成「匯入 → 驗證 → 調試 → 修正」的完整流程。

## 適用範圍

本指南涵蓋的項目：

- **書源**（文字小說／聽書／漫畫類型的 `bookSourceType` 0/1/2）
- 書源的 **搜索、發現（探索）、詳情、目錄、正文** 五個階段

不涵蓋的獨立系統（各有自己的設定介面與格式）：TTS 語音源、RSS 訂閱源、OPDS 目錄、WebDAV、替換規則。

## 1. 匯入書源

書源列表（App「書庫」→「書源」分頁）右上角點「**+**」，或按空狀態提示，即可開啟匯入：

- **貼上 JSON**：直接貼上 Legado 匯出的書源 JSON（單個 `{}` 或陣列 `[]` 皆可）
- **從文件選取**：支援 `.json`、`.yds`、`.xbs`、`.mrs` 檔案
- 匯入後可在書源列表用「更多 → 複製源／粘貼源」搬移書源 JSON

## 2. 測試書源：五階段驗證

匯入後第一件事：在書源列表**長按（或左滑）書源 →「測試書源」**，對單一書源跑五階段驗證：

| 階段 | 檢查內容 |
| --- | --- |
| 檢查搜索 | 用測試關鍵字搜尋，解析 `ruleSearch.ruleBookList` |
| 檢查發現 | 解析 `exploreUrl` 與 `ruleExplore.ruleBookList` |
| 檢查詳情 | 實際抓取第一本書的詳情頁並解析 `ruleBookInfo`；搜索結果即使已有目錄 URL 也不會略過 |
| 檢查目錄 | 使用詳情階段產生的 URL 與運行變數抓取目錄，驗證至少有可載入章節並檢查常見 API 錯誤包裝 |
| 檢查正文 | 抓取並解析第一個可載入章節，驗證實際正文不為空 |

驗證結果頁會顯示五個階段各自的通過／失敗狀態（⚪ 綠＝通過，紅＝失敗）、每階段耗時（毫秒），失敗的階段再依 `FailureCategory` 分類：

| 分類 | 含義 | 通常是誰的問題 |
| --- | --- | --- |
| 規則缺失 | 書源根本沒填該階段的規則欄位，或規則為空 | 書源作者 |
| 解析失效 | 有規則但解析後結果為空／錯誤 | 規則與網站現況不符，或用到本 App 不支援的語法 |
| 環境問題 | 網路、防護（Cloudflare）、登入等外部因素 | 網站／使用者環境 |

書源列表每一行會顯示徽章：**驗證通過**、**抓取異常**、**正文異常**，以及最近一次響應毫秒數；列表頂部可篩選「全部／抓取異常／正文異常」。

> 單次驗證所有書源：書源列表右上角「書源驗證」→「開始驗證」（可勾選要檢查的階段，測試關鍵字預設為書架上該來源的書名）。

## 3. 調試規則：逐步日誌

驗證只能告訴你「哪個階段失敗」；要知道「**哪一條規則、哪一步**失敗」，用規則調試器：

「書源」分頁點開書源 → **編輯書源** → 右上角「⋯（更多）」→「**調試規則**」。

調試器有五個分頁：**搜索／詳情／目錄／正文／全流程**。輸入關鍵字（搜索、全流程）或 URL（詳情、目錄、正文）後按「執行」，日誌會逐步印出：

1. **原始數據**：收到的 HTML／JSON 類型與長度（前 200 字元預覽）
2. **規則解析**：規則被拆成哪些段落、各段模式（CSS／XPath／JSON／JS／Regex）
3. **提取 #n**：每一段規則的輸入與提取結果
4. **正則替換 #n**：`##pattern##replacement##` 替換前後對照
5. **JS 執行 #n**：執行的 JS 與回傳值（出錯時會看到 `ERROR:`）
6. **最終值／最終列表**：整條規則鏈的最終輸出與耗時

對照 Legado 的經驗：日誌格式刻意採用與 Legado `BookSourceDebugActivity` 相同的標記（`[Rule Parsed]`、`[String Extracted #n]`、`[Final Result]`…），熟練 Legado 調試的用戶可以無縫對照。

**判讀原則**：從「最終值」往回找第一個顯示「（空）」或 `ERROR` 的步驟——空結果的那一段就是斷點。

## 4. 需要登入的書源

書源編輯器「基本」分頁有**登入頁 URL**、**登入 UI**、**登入檢查 JS** 三個欄位：

- 填了登入頁 URL 的書源，可在書源列表長按 →「**Cookie 驗證登入**」用內建瀏覽器登入
- **登入檢查 JS**：登入後在搜索響應上執行，判定是否仍被導向登入頁；非空時搜索前會先檢查登入狀態
- 登入取得的 cookie 會自動保存並在後續請求帶上（詳見[與 Legado 的差異](legado-differences.zh-Hant.md)）

## 5. 回報問題前，先準備這些

向書源作者或本專案回報書源問題時，請附上：

1. **書源 JSON**（書源列表 → 更多 →「複製源」）
2. **失敗階段的調試日誌**：編輯書源 → 更多 →「調試規則」跑對應分頁，把結果截圖（若只截圖，請展開可疑的那幾條日誌看完整內容）
3. **一句話描述**：哪個階段失敗（搜索無結果／目錄空白／正文空白…）、在 Legado 上是否正常

先對照[常見症狀對照表](troubleshooting.zh-Hant.md)，多數問題在 App 內就能自己修好。
